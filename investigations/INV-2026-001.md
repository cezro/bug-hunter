# Investigation Record: Arbitrary Enterprise LLM Model Selection & Unauthorized Consumption in Newfold AI Gateway

## 1. Initial Anomaly & Discovery
- **Target Subsystem / Endpoint:** `POST https://api-gw.builderservices.io/ai-api/v3.0/chat`
- **Discovery Date:** 2026-10-31
- **Discovery Context:** While inspecting network traffic from the Bluehost Account Manager (`www.bluehost.com/my-account/hosting/details/sites`) AI Assistant widget, the client was observed sending the Azure OpenAI deployment name directly in the request payload:
  ```json
  "OpenAiChatOptions": {
    "Model": "bluehost-help-gpt4.1-mini",
    "hasAzureAiSearch": true,
    "HasCustomFunctions": true,
    ...
  }
  ```

---

## 2. Hypothesis & Threat Model
- **Hypothesis:** The AI Gateway accepts arbitrary `Model` names provided by the client and substitutes them directly into Azure OpenAI deployment requests (`https://<resource>.openai.azure.com/openai/deployments/{Model}/chat/completions`) without verifying whether the authenticated user or application tier is authorized to execute against high-cost enterprise models (such as `gpt-4o` or `gpt-4o-mini`).
- **Vulnerability Class:** CWE-285: Improper Authorization / OWASP LLM04: Model Denial of Service & Resource Exhaustion / OWASP LLM07: System Information Leak
- **Root Cause Category:** Authorization / API Security

---

## 3. Investigation Steps & Observed Responses

### Test Case A: Baseline Authorized Request (`bluehost-help-gpt4.1-mini`)
```http
POST /ai-api/v3.0/chat HTTP/1.1
Host: api-gw.builderservices.io
Authorization: Bearer <RESEARCHER_USER_TOKEN>
Content-Type: application/json

{
  "PromptId": "85756fc6-f4f0-4861-abae-645106d379b5",
  "SessionId": "988ee60f-5b82-4092-a3c5-93addd7ad7ef",
  "OpenAiChatOptions": {
    "Model": "bluehost-help-gpt4.1-mini",
    "hasAzureAiSearch": false,
    "HasCustomFunctions": false,
    "messages": [{"role": "user", "content": "test"}]
  }
}
```

**Observed Response:**
```json
{
  "transactionId": "75c61110-592e-4e79-81a0-d09c9d292015",
  "openAiResponse": {
    "id": "chatcmpl-EexOUl10bq4Spw0Z7epzAUC63uppB",
    "model": "gpt-4.1-mini-2025-04-14",
    "deploymentName": "bluehost-help-gpt4.1-mini",
    "usage": { "prompt_tokens": 1695, "completion_tokens": 18, "total_tokens": 1713 }
  },
  "success": true
}
```

```http

Authorization: Bearer <RESEARCHER_USER_TOKEN>

{

**Observed Response:**

    "deploymentName": "gpt-4o",

  "success": true

```

### Test Case C: Backend Topology & Deployment Enumeration
- `Model: "gpt-4o"` -> HTTP 200 `success: true`, `deploymentName: "gpt-4o"`
- `Model: "gpt-4o-mini"` -> HTTP 200 `success: true`, `deploymentName: "gpt-4o-mini"`
- `Model: "netsol-help-gpt4.1-mini"` -> HTTP 200 `success: true`, `deploymentName: "netsol-help-gpt4.1-mini"` (Cross-Brand model!)
- `Model: "dall-e-3"` -> HTTP 200 `success: false`, `deploymentName: "dall-e-3"`, error: `"BadRequestForDependentService"` (Azure OpenAI upstream error verbatim)
- `Model: "nonexistent-model"` -> HTTP 405 `{"message": "Invalid model", "success": false}`

---

## 4. Current Findings & Evidence
1. **Financial and Compute Resource Exhaustion:** Any user registered with a zero-cost free trial can repeatedly invoke enterprise `gpt-4o` models via Newfold's central AI Gateway.
2. **Cross-Brand Deployment Access:** Bluehost users can target models deployed for other OneWeb brands (e.g. `netsol-help-gpt4.1-mini` for Network Solutions).
3. **Deployment Topology Enumeration:** Verbatim Azure OpenAI upstream error messages and deployment names are reflected back in API responses.
